# 随译 Suiyi

Mac 全局翻译助手（原名 Fanyi），中英日韩粤任意互译，界面支持简体中文、English、日本語、한국어。

一个只住在菜单栏里的个人划词翻译 / 改写工具。选中文字 → 点小圆按钮 → 直接出翻译，卡片顶部可切到「改写」，结果以流式方式显示在浮动卡片里。使用任何 OpenAI 兼容接口（默认 DeepSeek）。

- 无遥测；历史记录、画像自动更新和我的风格均需主动开启，首次安装默认关闭；Codex / Claude Code 接入只在点击接入按钮后执行。API Key 存在系统钥匙串（service：`ai.mars.suiyi`）。
- 不在排除列表中的应用、密码输入框、开启了“安全键盘输入”的场景中触发。

## 从 Fanyi 升级

随译首次启动时会自动迁移一次，旧数据不删除：

- 设置：从 `ai.mars.fanyi` 复制到 `ai.mars.suiyi`（已有的新设置不覆盖）。
- API Key：从钥匙串 service `ai.mars.fanyi` 复制到 `ai.mars.suiyi`。macOS 可能弹窗询问是否允许随译读取，选「允许」；拒绝则需在设置里重新填写。
- 数据：`~/.fanyi` 移动为 `~/.suiyi`，原位置留一个指向新目录的符号链接，已有引用（如 `@~/.fanyi/profile.md`）继续可用。
- Codex / Claude Code 接入：`AGENTS.md`、`CLAUDE.md` 中旧的 Fanyi 标记块会替换为随译标记块，路径改为 `~/.suiyi/profile.md`。
- 签名：未创建随译签名身份时，`build.sh` 会继续使用之前的 `Fanyi Local Signing`。

bundle id 变了，需要在 **辅助功能** 中重新授权随译。确认正常后，可手动删除旧版 `~/Applications/Fanyi.app`，并在登录项、辅助功能列表中移除 Fanyi。

## 环境

- macOS 13 及以上
- 只需 Command Line Tools（`xcode-select --install`），不需要 Xcode.app

## 构建

```bash
cd fanyi  # 仓库目录名暂未改
./build.sh
```

产物：`build/Suiyi.app`（App 图标由 `Resources/AppIcon.png` 在构建时生成 `AppIcon.icns`）（bundle id `ai.mars.suiyi`；优先使用稳定本地签名，身份不存在时回退 ad-hoc）。

## 打包分发

```bash
./scripts/package.sh
```

产出 `dist/Suiyi-<版本>.zip`（`ditto` 打包，保留签名）并打印 SHA-256。压缩包里是 `Suiyi.app` 和一份中英日韩安装说明（`Resources/Distribution/`），直接发给同事即可。用本机签名时，同事首次打开需在 **系统设置 › 隐私与安全性** 点「仍要打开」。

有 Apple Developer ID 时可产出公证版本，双击即开、无警告：

```bash
xcrun notarytool store-credentials suiyi-notary --apple-id <Apple ID> --team-id <TEAMID>
SUIYI_SIGN_IDENTITY="Developer ID Application: <名称> (<TEAMID>)" SUIYI_NOTARY_PROFILE=suiyi-notary ./scripts/package.sh
```

使用 Developer ID 签名时，`build.sh` 会自动开启 hardened runtime 和安全时间戳；脚本随后提交公证、装订票据并用 `spctl` 校验。

## 检查与自动更新

- 菜单 **检查更新…** 随时手动检查；设置 › 行为 › **自动检查更新**（默认开启）会在启动后和之后每天检查一次。检查只读取官网的 `latest.json`，不发送任何个人数据；关闭后只在手动点击时检查。
- 有新版时提示 **立即更新**：下载该版本的 `Suiyi.zip`，先核对 `latest.json` 里的 SHA-256，再确认新 App 与当前 App 由同一证书签名、bundle id 相同，然后原地替换并重新打开。设置、钥匙串里的 API Key 和辅助功能授权都会保留。任一校验不通过就不安装，并提供「前往下载」。
- 只接受 `https://github.com/mars16881688/fanyi-site/releases/download/…` 下的 zip。

发布新版：

1. 改 `build.sh` 中的版本号，运行 `scripts/package.sh`，记下打印的 SHA-256。
2. 在官网仓库 `mars16881688/fanyi-site` 创建 Release（tag `v<版本>`），附件名固定为 `Suiyi.zip`：
   `cp dist/Suiyi-<版本>.zip /tmp/Suiyi.zip && gh release create v<版本> /tmp/Suiyi.zip --repo mars16881688/fanyi-site --title "随译 <版本>" --notes "…"`
3. 更新官网仓库的 `latest.json`：`version`、`url`（Release 页面）、`notes`，以及自动更新所需的 `download`（`https://github.com/mars16881688/fanyi-site/releases/download/v<版本>/Suiyi.zip`，必须是这个版本自己的地址）和 `sha256`（第 1 步的值）。缺少后两项时，App 只提示「前往下载」。

官网下载按钮固定指向 `https://github.com/mars16881688/fanyi-site/releases/latest/download/Suiyi.zip`，发新版不用改链接。

## 反馈与自动处理

- 菜单 **反馈…**：选择「问题 / 建议」并描述，点「在 GitHub 提交」会在浏览器打开预填好的 issue（公开仓库 `mars16881688/fanyi-site`），由用户确认提交；也可「发邮件」。只附带版本号、macOS 版本和语言设置，不附带任何选中文字。
- 每天一次的 Claude Code 云端定时任务读取新反馈：判断是否有效、分类打标签并回复；可修复的在本仓库开 `feedback/<编号>` 分支的 PR，不会合并。
- `.github/workflows/test.yml` 在每个 PR 上用 macOS 运行 `swift test`，合并前看 CI 结果。

## 图标

`Resources/AppIcon.iconset` 由 `swift scripts/make-icon.swift Resources` 以矢量逐尺寸渲染（16 px 到 1024 px 各自按原生像素绘制，小尺寸去阴影、加描边），`build.sh` 直接用它生成 `AppIcon.icns`。改图标设计后重新运行该脚本。

## 测试

```bash
swift test
```

使用 Swift Testing，覆盖接口地址拼接、错误提示、SSE 流解析、语言方向判断、提示词、改写解析、设置解析、Fanyi 数据迁移、agent 标记块，以及选区按钮和结果卡片的浅色 / 深色渲染。设置 `SUIYI_SNAPSHOT_DIR=<目录>` 可把界面快照导出为 PNG 供人工检查。测试只使用临时目录和测试专用的 defaults 域，不读写真实设置、钥匙串或 `~/.suiyi`。

## 稳定签名（避免反复授权辅助功能）

每位用户应在自己的 Mac 上创建自己的本地证书；不要共享证书或私钥。在 Mac 上运行一次：

```bash
scripts/create-signing-cert.sh
./build.sh
```

脚本会在你自己的专用钥匙串 `~/Library/Keychains/suiyi-signing.keychain-db` 中创建有效期 10 年的自签名代码签名证书 `Suiyi Local Signing`，该钥匙串的随机密码保存在你的登录钥匙串里，因此 `build.sh` 签名时不会弹出钥匙串授权框。证书和私钥文件只写入系统临时目录，脚本退出时清理，不写入仓库。（可选：`SUIYI_TRUST_CERT=1` 会把证书标记为受信任，需要输入密码；稳定授权并不需要。）首次使用新身份构建并安装后，在 **辅助功能** 中删除并重新添加 随译，最后重新授权一次。之后使用同一证书重新构建即可保留权限。

自定义身份可用 `SUIYI_SIGN_IDENTITY="你的证书名称"`（创建证书和构建均支持）；构建也兼容原来的 `SIGN_ID`，优先级低于 `SUIYI_SIGN_IDENTITY`。身份不存在时会显示警告并回退 ad-hoc，构建会打印实际使用的身份。不会启用 hardened runtime。

## 安装

```bash
./install.sh
```

每次都会先用当前代码重新构建，再把 App 复制到 `~/Applications/Suiyi.app`（目录不存在会自动创建），结束正在运行的随译并重新打开。

## 授予辅助功能权限

首次启动会弹出系统提示。请打开：

**系统设置 › 隐私与安全性 › 辅助功能**，找到 随译 并打开开关。

没有这个权限就无法读取选中文字、也无法模拟 ⌘C / ⌘V。菜单里的“授予辅助功能权限…”可以随时跳转过去。授权后建议退出并重新打开一次 随译。

> 若构建回退到了 **ad-hoc 签名**：签名会随二进制变化，系统可能认为这是“另一个 App”，辅助功能开关看起来是开着但实际无效。此时请在列表里**选中 随译 点“−”删除，再点“+”重新添加** `~/Applications/Suiyi.app`，然后重启 随译。钥匙串也可能会再次询问是否允许访问 API Key，选“始终允许”即可。

## 设置 API Key

点击菜单栏图标 → **设置…**：

- **API Key**：保存到钥匙串
- **Base URL**：默认 `https://api.deepseek.com/v1`（会自动拼接 `/chat/completions`）
- **模型**：默认 `deepseek-chat`
- 任何 OpenAI 兼容服务都可以，例如 OpenAI（`https://api.openai.com/v1`）、OpenRouter（`https://openrouter.ai/api/v1`）、本地 Ollama（`http://localhost:11434/v1`）等
- **测试连接**：用当前填写的内容发一个很小的请求，显示成功或错误信息
- **我的语言** / **常用对外语言**：中文 / English / 日本語 / 한국어 / 粵語。外语一律译成我的语言；选中的已是我的语言时，译成常用对外语言。中英日韩粤任意两两互译。粤语指香港粤语口语（繁体字）：选中的中文里出现「嘅、咗、唔、喺、冇、哋」等粤语用字时按粤语识别，译成普通话；常用对外语言选粤语时，中文会译成粤语口语。首次安装按系统语言选择；从旧版升级时，原「目标语言：自动」对应「我的语言 = 中文，常用对外语言 = English」。
- **划词后显示按钮**、**开机启动**、**排除的应用**（Bundle ID，逗号分隔）

改完点 **保存**。

## 使用

- **划词**：用鼠标拖选或双击 / 三击选中文字，鼠标旁会出现一个小圆按钮，点一下直接翻译（悬停不会触发请求）。4 秒不理会、点击别处或按 Esc 会自动消失。
- **翻译 / 改写 tab**：结果卡片顶部可在 **翻译** 和 **改写** 之间切换，卡片位置不变；同一段选中文字已出过的结果会缓存，来回切换不重复请求。
- **快捷键**（不显示小按钮，直接出结果）：
  - `⌥⌘T` 翻译选中文字
  - `⌥⌘R` 改写选中文字（同语言给出 更简洁 / 更正式 / 更口语 三个版本）
  - `⌥⌘P` 朗读选中文字，并在卡片里给出读法（中文拼音、日文假名与罗马字、韩文罗马字、英文 IPA）；朗读使用系统语音，不联网
- **结果卡片**：可拖动；**复制**、**替换**（仅当原位置可编辑时出现，会直接替换选中内容或用粘贴方式替换）；右上角 **×**、Esc 或点击卡片外部关闭。
- **回复**：外语译成我的语言后，译文右侧是小的复制图标（这种卡片底部不再放大按钮）；点击译文下方的 **用（我的语言）回复** 展开输入框；输入多行回复，按 `⌘↩`（Return 换行）生成，回复会译回对方原文的语言（日文消息回日文，英文消息回英文）。翻译回复时会把对方原话作为上下文发给模型，让「10 点」这类简短回复按语境译得自然，但不添加你没写的内容。回复生成后「复制」成为主按钮。
- **界面语言**：菜单、设置、卡片和报错跟随系统语言显示简体中文、English、日本語或한국어，其他系统语言显示英文。
- 菜单中的 **暂停划词** 只停用鼠标划词，快捷键仍可用。

翻译时会把当前应用名、窗口标题（聊天应用不发，那通常是对方的名字）和选区附近的文字作为“背景信息”发给模型，帮助判断语境和语气（终端 / 代码、聊天、邮件、浏览器、文档）。Bundle ID 和网页地址不会发出去。

## 历史、画像与我的风格

在设置的 **历史与画像** 中开启或关闭「记录历史」（默认关闭，首次开启会说明数据用途并要求确认，取消保持关闭；点保存生效），查看条数、打开文件夹或确认后清空历史。仅记录成功完成的请求，排除列表中的应用、错误和提示不会记录。文件为 `~/.suiyi/history.jsonl`（权限 0600），目录权限 0700；回复记录包含对方原文、译文、你写的回复及发出的回复（字段名 `reply_zh` / `reply_en` 沿用旧版，分别表示你写的和发出的内容）。

「记录历史」和「回复时参考我的风格」都开启、且已配置 API Key 时，每新增 30 条记录自动生成 `~/.suiyi/profile.md`（画像只有「我的风格」会读）；只开「记录历史」时，需要手动点 **更新我的画像**。自动更新失败后不会每条记录都重试，切换了模型接口后旧历史也不会自动发给新接口。使用最近最多 200 条记录和已保存的模型配置，失败时保留旧画像。可在画像的 **我的补充** 下写个人偏好，重新生成会原样保留该部分；清空历史不会删除画像。

**接入 Codex / Claude Code** 默认不接入，启动、保存设置和生成画像均不会自动安装。只有点击该按钮才会向 `~/.codex/AGENTS.md`、`~/.claude/CLAUDE.md` 添加带随译标记的画像引用。设置了 `$CODEX_HOME` 时，Codex 使用该目录的 `AGENTS.md`（相对路径基于当前用户的主目录解析）；目标必须在当前用户主目录内，不能位于 Git 仓库中，符号链接也会校验。重复点击会更新该块；「移除接入」只移除该块，保留原有内容和文件权限。

**回复时参考我的风格** 默认关闭（需主动开启，点保存生效），只读取当前用户自己的 `~/.suiyi/profile.md`、`~/.codex/AGENTS.md`（或 `$CODEX_HOME/AGENTS.md`）和 `~/.claude/CLAUDE.md` 中的个人偏好，帮助回复在译成对方语言时匹配语气、长度和用词。不会用于普通翻译，也不会改变回复内容。设置会显示找到的来源。

## 安全（敏感内容守卫）

始终开启（来自 Kimi 的 0.2.1.k 修改）：

- 密码类应用（钥匙串访问、密码、1Password、Bitwarden、KeePassXC 等）、密码管理网页和浏览器密码页不读取；标题像密码页的原生窗口需确认。
- 选中内容像密钥、令牌、卡号、身份证号、助记词、恢复码时不弹按钮；用快捷键需在 10 秒内对同一段文字再触发一次才发送，且不记入历史，复制时标记为 Concealed / Transient。
- 像密钥的窗口标题、附近文字和风格资料中的可疑行不发送；画像生成跳过可疑记录。
- 模型接口只接受 https（本机 http 除外），不跟随重定向；剪贴板里有密码管理器内容时不模拟 ⌘C，还原时仅限本机。
- 浏览器选区优先用文本标记接口读取，不经过剪贴板。

设置里的相关选项：**翻译风格**（口语倾向，默认 / 商务倾向）、**在终端和代码编辑器中启用**（默认关闭）、**鼠标划词读不到文字时，也显示按钮**（默认开启；划词时不发按键，点了按钮才模拟一次 ⌘C 读取）。菜单 **最近一次划词** 显示上次没读到文字的原因（不含内容）。

## 隐私

历史记录、我的风格和 agent 接入均为 opt-in，默认关闭；自动画像更新需历史记录和我的风格都开启。所有个人数据和接入文件仅保存在各用户自己的主目录中，仓库不保存这些数据。历史与画像保存在 `~/.suiyi/`，不会自动上传，无新增服务、密钥或遥测。翻译、改写及回复仍发送到你配置的 API；画像生成也会将受长度限制的最近历史发送到同一个 API，并要求模型匿名化示例及省略秘密。开启「我的风格」时，读取到的风格背景会随回复请求发送到该 API。使用本地模型接口时，这些请求也可留在本机。

## 小提示

- 有些应用（如微信、Telegram）不通过辅助功能提供选中文字。在这些应用里拖选后照样会出现按钮，但划词时不发任何按键；**点了按钮** 才模拟一次 ⌘C 读取，然后恢复你原来的剪贴板（图片、PDF 等无法廉价复制的内容不会恢复；这期间你自己按了 ⌘C 则保留你复制的内容）。拖动窗口或滚动条不出按钮；双击选词不会使用这种方式。
- 虚拟机和远程桌面（Parallels、VMware、UTM、Windows App、屏幕共享、VNC、TeamViewer、Try Omarchy 等）里永远不模拟按键：先在里面复制，再按 `⌥⌘T` 翻译剪贴板里的文字。
- 菜单里的 **在「当前应用」中停用随译** 可一键把前台应用加入排除列表，再点一次取消。
- 如果 `⌥⌘T` / `⌥⌘R` 被其他应用占用，快捷键会注册失败，可以从菜单里操作。
